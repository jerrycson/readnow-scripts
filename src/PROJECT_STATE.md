# 리드나우 — 프로젝트 상태 (대화가 압축·새로 시작돼도 이어 가기 위한 기준 문서)

새 대화·자동 점검은 **이 파일 → README.md → 웹앱 `UPDATE_LOG`(src/app.html)** 순서로 읽고 시작합니다.
작업을 끝낼 때마다 아래 '정한 규칙'·'남은 일'을 고칩니다(지난 내용은 지우지 말고 고쳐 씀).

## 구성
- 웹앱 `src/app.html` → `app/` · 수집기(Tampermonkey) `src/readnow-collector.src.js` → 맨 위 `readnow-collector.user.js` + `readnow-pc-*.js` + `pc-live.json`(⚡ 5분마다 확인하는 빠른 업데이트)
- 공용 파일 `readnow-*-core.js` · 판 목록 `readnow-registry.js`(PINS = 웹앱·수집기·클라우드가 쓰는 공용 파일 판)
- 클라우드 `cloud/index.js`(Cloud Run readnow-cloud) — `cloud/**`·공용 파일이 바뀌면 GitHub Actions가 저절로 배포(CODE_SHA = 올린 커밋)
- 만들기: README의 '다시 만들기' → `node split.js && node release.js`(판 번호·핀이 하나라도 틀리면 멈춤)

## 사장님이 정한 일하는 방식 (늘)
- 한국어로 자세히 · 바꿀 때마다 설명서·CHANGELOG·UPDATE_DATES·UPDATE_LOG 함께 · 수집기에도 같이 반영
- 모은 자료는 지우거나 덮지 않음 — 원인·결과 분석에 안 쓰는 기록만, 주간 백업에 들어간 뒤에만 지움
- 기준을 지어내지 않음 · 사람 손으로 하는 과정 만들지 않음 · 넘기기 전에 확인(시험)
- 브라우저 팝업 대신 화면 안 두 번 누르기 · 바로 적용되는 스위치는 알림(토스트) · 정렬 단추는 한 번 = 정렬, 또 = 반대
- 오래 걸리는 내려받기 = 진행판 + 이어 받기 · GitHub(jerrycson/readnow-scripts)에 직접 올림
- '새상품' = 공장 새것만 · '새등록 상품' = 우리가 등록하는 것 · '이것부터' = 그것 먼저
- 보안: Tampermonkey 저장소 내보내기(*.storage.json, rn-cred)는 열지도 공유하지도 않음 · 알라딘 계정은 Secret Manager(ALADIN_ID·ALADIN_PW·TICK_KEY)에만
