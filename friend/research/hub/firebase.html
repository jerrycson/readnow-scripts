Firebase 설정과 회차 보존

프로젝트는 readnow-3a385입니다. Hosting은 운영 페이지·공개 자료와 암호화한 보고서·계획표를 제공하고, 전용 Firestore는 관리자 열람과 회차 알림을 담당합니다. 새 기록은 새 주소를 갖습니다. 폐기한 시안도 원문과 사유를 유지합니다.

  1. Hosting의 기존 사이트 readnow-3a385와 도메인 readnow.kr을 사용합니다. 운영 프로젝트 탭의 책방 친구 연구 버튼이 연구실을 엽니다. 페이지는 열려 있는 동안 15초마다 새 회차를 확인합니다.
  2. Firebase Console의 Authentication → Users에서 본인의 기존 계정 UID를 확인하세요. Authentication → Settings → Authorized domains에 readnow.kr이 있는지 확인합니다. 기존 앱에 로그인된 같은 브라우저를 사용하세요. 새 계정을 만들 필요는 없습니다.
  3. 관리자 자료 묶음 ZIP을 로그인된 Cloud Shell의 메뉴 → Upload로 올리세요. 터미널에서 unzip -n bookfriend-firebase.zip -d bookfriend-import 다음 cd bookfriend-import && node cloud-import.mjs bookfriend-import.json을 실행한 뒤 본인 UID를 입력합니다. 충돌을 피하려면 새 회차에는 새 폴더에 풉니다. 묶음과 열람 파일은 관리자만 보관하세요.
  4. 스크립트는 서울 리전의 새 Firestore Native 데이터베이스 readnow-research를 생성할 때 삭제 방지를 켭니다. 기존 기본 데이터베이스와 번외 수집기 col2_*에는 쓰지 않습니다. 사전에 추가 데이터베이스를 사용할 수 있는 결제 요금제와 Firestore 생성·데이터 읽기/쓰기·Firebase Rules 게시 권한이 필요합니다. 기존 전용 규칙이 다르면 중단합니다.
  5. 전용 규칙은 로그인 사용자의 자기 열람 문서만 단건 조회하도록 하고, 등록된 독자에게 회차와 원문 조각 읽기를 허용합니다. 브라우저의 쓰기는 허용하지 않습니다. 셸의 작성 권한으로 내용 해시별 원문을 먼저 쓰고 재조회한 후 회차 문서를 하나 추가합니다. 같은 ID가 다른 내용을 담고 있으면 중단합니다.
  6. 연구실 → 밤샘 보고서 → Firebase 관리자 연결로 엽니다. 다른 브라우저에서 새 회차를 등록하면 Firestore 구독 알림과 Hosting 회차 목록을 읽습니다. Firestore 구성 전에는 관리자 열람 파일로도 해당 판의 문서를 볼 수 있습니다. 화면의 마지막 확인 시각과 회차 ID를 비교하세요.
