# 우리숍 늦은 응답과 다른 탭 장바구니 보존 — 2026-11-16

## 재현과 수정

고객 복구 PR #12의 963d62dfaf0ccf7e6980f1c769b4c11d56cc7533을 기준으로 한다. 실제 Edge 두 탭에서 한 탭의 재고/견적 응답을 늦추고 다른 탭의 화면으로 상품을 삭제 후 다시 담았다. 이전 응답이 도착하면 새로 담은 한 건이 0건이 되는 두 경로를 확인했다. 떠난 화면의 cartFresh도 현재 저장 목록을 바꿨고, syncCart는 새 줄의 식별자와 상관없이 상품 번호만 보고 지웠다.

재고와 견적 요청은 같은 시점의 장바구니를 사용한다. 응답이 돌아오면 현재 줄 식별자·수량·가격 등을 포함한 목록 전체가 같은지 확인한다. 다른 목록이면 그 응답으로 저장 내용을 바꾸지 않는다. 떠난 화면의 재고 응답도 적용하지 않는다. 현재 장바구니 화면은 변경 내용을 다시 표시하고, 주문서의 견적은 변경된 목록으로 한 차례 다시 확인한다.

주문서에서 보여준 목록과 제출 시점의 목록이 다르면 접수를 보내지 않고 상품·합계를 다시 확인하도록 안내한다. 이름·주소 등 작성한 칸은 보존한다. 견적 확인이 실패하면 앞선 합계로 접수하지 않는다. 확인 뒤 사용자가 다시 제출하면 새 수량과 확인한 합계로 기존 요청 장부 절차를 진행한다. 가격·할인 계산과 서버 예약 규칙은 바꾸지 않는다.

## 검증 범위

기존 핵심·구문 76/76, 앞선 변경과 합친 핵심·구문 204/204. 새 두 탭 회귀는 화면에서 삭제·다시 담기·수량 변경을 실행하며 재고/견적 응답만 합성 자료로 지연한다. PC 1280px와 휴대폰 390px에서 입력 보존, 첫 제출의 외부 접수 0회, 확인 후 새 수량·합계로 한 번 접수, 견적 실패 중 재제출 보류를 확인한다.

브라우저와 실제 함수·HTTP 통합의 최종 실행 결과는 PR 본문과 바통 쪽지에 기록한다. 모든 자료는 합성이며 바깥 서버 연결은 차단한다. 운영 주문·계정·배포 자료는 바꾸지 않았다.

이 수정은 늦은 비동기 응답의 적용 범위를 보호한다. localStorage의 두 탭 읽기/쓰기 전체를 원자적 거래로 바꾸지는 않았다. 실제 동시 쓰기 경합, 저장 실패의 사용자 안내와 기기 사이의 장바구니 공유는 별도 검토 대상이다. 실제 서버·인증·캐시 혼재·비공개 통합·실기기 확인도 남아 있다.
