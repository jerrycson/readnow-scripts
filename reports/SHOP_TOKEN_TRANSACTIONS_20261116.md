# 로그인 소유권 거래 보완 검토 — 2026-11-16

기준: 고객 화면 PR #25의 `07fffb04edd71e5397204fd054102d716f87d0c1`. 구현·시험용 초안이며 운영 반영 완료 기록이 아니다. 수정 파일은 로컬에 보관했으며 새 코드 PR 발행·CI는 아직 진행하지 않았다.

## 재현한 결함

기존 Web Locks + localStorage 비교·교체는 실제 고객 화면의 두 탭에서 두 작성자가 모두 성공하는 경우가 있었다. 가짜 자료를 사용한 반복 검사에서 60회 중 1회, 추적을 붙인 별도 100회 중 1회 재현했다. 추적에서는 첫 탭이 저장 후 잠금을 놓은 다음 두 번째 탭이 같은 잠금을 받았지만 이전 값을 읽었다. 최소 모듈만 검사한 별도 200회는 모두 통과했으므로 그 결과만으로 전체 앱의 실패를 없던 일로 처리하지 않았다.

[WHATWG Web Storage 문서](https://html.spec.whatwg.org/dev/webstorage.html)는 여러 프로세스의 저장소 상호작용에 잠금 보장을 가정하지 말 것을 설명한다. 이 근거와 재현 결과에 따라 임의의 지연을 넣는 방식 대신 거래 저장소를 사용한다.

## 최종 코드가 보장하려는 범위

- 로그인 소유권과 증가하는 변경 번호를 IndexedDB의 `meta`에 저장한다. 기존 `bq-tok`는 동기 화면 표시용 사본이다.
- 첫 이관은 한 거래 안에서 초기화 표와 소유권을 함께 생성한다. 이미 초기화된 장부의 소유권 행이 없거나 형식이 손상됐으면 사본으로 되살리지 않는다.
- 서버 요청 전에 변경 종류·기존 열쇠 해시·변경 번호·난수 작업표를 기록한다. 작업표는 준비 → 전송 → 완료 상태를 가진다.
- 같은 작업표는 한 번만 전송할 수 있다. 확정 결과의 반영은 소유권 변경과 완료 기록을 같은 엄격한 거래로 처리한다.
- 비회원 → 로그인 → 비회원처럼 열쇠 문자열이 다시 같아져도 변경 번호가 달라 옛 응답을 거절한다.
- 완료 거래 뒤 사본 쓰기·삭제·확인 읽기가 실패하면 같은 작업표로 기기 저장만 재시도한다. 다시 열린 화면도 장부에서 사본을 복구한다. 그 과정에서 이전 화면의 동작을 새 계정으로 대신 전송하지 않는다.
- 실제 fetch 호출 직전까지 Web Lock을 유지한다. 네트워크 응답은 잠금 밖에서 기다려 다른 탭의 진행을 막지 않는다. 계정 응답은 요청 당시의 변경 번호도 확인한다.
- 인증된 주문·계정 요청, 문의와 이용 기록의 실제 전송에 소유권 확인을 연결한다. 주문의 이미 접수된 응답·영수증은 기존 주문 장부 계약대로 보존한다.
- 구형 저장 모듈·계정 화면·요청 도구가 새 계약과 섞이면 인증 작업을 보류한다. 관리자 미리 보기는 실제 로그인 장부에 접근하지 않는다.
- 저장소 확인 실패를 로그아웃 확정으로 표시하지 않고 원인과 다시 확인하는 길을 보여 준다.

[IndexedDB 거래 일정 초안](https://w3c.github.io/IndexedDB/#transaction-scheduling)의 겹치는 쓰기 거래 순서 보장을 사용한다. [Web Locks 작업 초안](https://www.w3.org/TR/web-locks/)은 전송 호출의 짧은 임계 구간에 사용한다. 두 W3C 문서는 작업 중인 초안이며 최종 권고안으로 표시하지 않는다.

## 보존·호환 조건

현재 열쇠 원문은 기기의 기존 저장소와 새 소유권 행에만 있다. 과거 작업표에는 원문 대신 해시·종류·변경 번호·처리 상태만 보존한다. 암호·메일·회원 본문·문의·주문 본문을 작업표에 저장하지 않는다. 장부나 과거 작업표를 지워서 오류를 회피하지 않는다.

새 구현은 IndexedDB의 엄격한 완료와 Web Locks가 필요하다. 준비할 수 없으면 인증 작업은 보류하고 상품 목록 등 공개 읽기는 유지한다. 페이지 종료 때 비동기 소유권 검사가 끝나지 않은 이용 기록의 전송 완료는 보장하지 않는다.

이미 열린 구형 파일만으로 이루어진 탭에 새 코드가 저절로 적용되는 것은 아니다. Claude 배포에서는 관련 고객 자산을 함께 배포하고 캐시 갱신·기존 탭 재진입을 확인해야 한다. IndexedDB 기록을 보존한 채 되돌리는 방법도 통합 검토 대상이다. 구형 작성자로 단순 복귀하면 새 장부와 사본이 갈라지므로 안전한 되돌리기라고 간주하지 않는다.
