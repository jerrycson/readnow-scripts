# 고객 주문 시작 계정 보존 — 2026-11-16

## 확인한 문제

서버 PR24(`b31f863f66a4bd998fcbc596b1245cce92aac59e`)와 고객 PR21(`abcd0c0c8c39bb1cbadf79037b61022ba8fb75a6`)을 합친 로컬 합성 환경에서 재현했다. 회원으로 주문을 시작한 뒤 세션이 폐기되어 접수가 거절되고, 새로고침 과정의 회원 조회가 로그인 정보를 지우면, 앞선 미접수 주문을 비회원으로 다시 전송할 수 있었다. 실제 서버 함수·HTTP·고객 화면 시험은 기존 8건 중 이 1건이 실패했다. 운영에서 발생했다고 단정하지 않는다.

기존 주문 장부는 요청 번호·비밀값·본문 해시를 보존했으나 시작 계정을 저장하지 않았다. 서버가 아직 요청을 받지 않은 상태에서는 앞선 계정을 복원할 서버 기록도 없었다.

## 변경

- 새 장부 항목은 schema 2로 저장한다. 회원 번호에서 계산한 SHA-256 구분값 또는 명시적인 guest를 보존한다. 로그인 열쇠, 회원 번호 원문, 주문 본문, 이름·주소·동의를 장부에 추가 저장하지 않는다. 이 구분 해시는 인증 수단이나 익명화 보증이 아니다. 실제 권한 판단은 서버가 계속 맡는다.
- 동일 회원의 새 로그인 세션은 원래 요청 번호·비밀값·동일 본문으로 재시도할 수 있다. 다른 회원, 회원→비회원, 비회원→회원 전환으로 원래 요청을 재전송하지 않는다.
- 주문서를 열 때의 계정을 확인하고, 장바구니 준비 전후·장부 저장 또는 본문 비교 이후·실제 HTTP 전송 직전에 다시 검사한다. 전송에 사용할 로그인 열쇠와 화면 유효성도 API에 명시한다.
- 다른 계정이면 결과 조회·미접수 요청 닫기를 유지하며, 원래 계정으로 돌아갈 안내를 제공한다. 이미 서버가 접수한 결과는 현재 계정과 무관하게 기존 비밀값으로 복구하며 주문을 복제하지 않는다.
- 계정 정보가 없는 schema 1 기록은 현재 로그인으로 소유자를 추정하지 않는다. 결과 조회·확정·미접수 닫기·완료 확인·영수증 보존은 유지하고 재전송만 막는다.
- IndexedDB 이름과 DB 버전은 유지한다. 기존 기록을 일괄 수정·삭제하거나 재작성하지 않는다. 구형 호출처럼 시작 계정 인수가 없으면 새 기록을 만들지 않는다. 새 고객 코드와 구형 장부 모듈이 섞이면 주문을 보류한다.

## 시험 누락 방지와 의존 관계

고객 브랜치는 PR21 위에 쌓는다. 서버 구현 파일은 이 PR에 복사해 올리지 않는다. CI가 서버 의존 코드가 없는 고객 브랜치를 검사할 때 PR24의 정확한 커밋을 별도 checkout하여 합성 서버 시험에만 사용한다. 서버 코드가 이미 있으면 작업본의 서버 코드를 검사하며 통합 시험을 생략하지 않는다.

`tACCOUNTAUTHUI`를 공개 CI와 변경 경로별 필수 시험에 연결했다. 고객 주문·장부·로그인·토큰 저장, 서버 주문·계정·예약·요청 계약, 해당 회귀 시험을 고치면 필수 검사에 포함된다.

PR24에 먼저 추가한 같은 이름의 브라우저 시험 파일은 이 PR의 확장된 21건 버전을 유지해야 한다. 병합 시 `run.cjs`, `test-policy.cjs`, `stability.yml`은 서버·고객의 시험을 합쳐 보존한다. 한쪽 파일 전체로 덮어쓰지 않는다.
