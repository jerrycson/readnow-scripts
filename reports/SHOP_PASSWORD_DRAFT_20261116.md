## 구현

비밀번호는 클릭 시점에 읽고 고정한다. 입력을 계속 편집할 수 있지만 대기 중 편집이 이미 결정한 요청을 바꾸지 않는다. 저장 잠금 이후와 실제 API 전송 직전에도 계정·화면이 유효해야 한다. 중복 제출은 한 번만 보낸다.

서버 변경 성공, 기기 로그인 열쇠 저장, 동일 회원 확인을 구분한다. 새 열쇠 저장 뒤 서버에서 같은 회원임을 다시 확인하고 현재 소개·목표·비밀번호 폼의 요청 소유자를 갱신한다. 화면 전체를 다시 만들지 않으며 입력·포커스·커서를 다른 폼이나 저장소로 복사하지 않는다. 확인된 회원 요약과 목표 진행률만 갱신한다.

그대로 둔 제출 비밀번호는 비운다. 제출 후 다시 편집한 입력은 값이 원래 값으로 돌아왔더라도 보존하고 다음 변경 때 확인하도록 안내한다. 작성 중인 소개·목표는 다음 명시적 저장에만 보낸다. 갱신된 폼도 이후 다른 로그인으로 바뀌면 저장을 보류한다.

전송 전에 화면을 떠나면 변경을 시작하지 않는다. 전송 후 이미 확인된 새 열쇠는 화면을 떠났더라도 기기에 안전하게 보존한다. 현재 화면의 내용은 덮지 않는다.

기기 저장 실패는 기존 저장 재시도를 유지하고 비밀번호를 다시 보내지 않는다. 새 회원 조회 실패도 비밀번호 변경 실패로 표시하지 않고 조회만 재시도한다. 확인 조회는 중복 실행하지 않으며 늦은 이전 로그인 응답이 새 회원 캐시를 되돌리지 않는다. 소개·목표도 각 제출의 시작 세션을 끝까지 확인하여 폼 연결을 갱신하기 전의 응답과 구분한다.

서버 오류·응답 유실·새 열쇠 없는 성공 응답은 결과 불명으로 안내한다. 현재 폼에서 같은 변경을 다시 보내지 않고 로그인으로 확인하도록 한다. 이 결과 불명 표시는 현재 폼의 메모리에만 있다. 새로고침 뒤까지 이어지는 서버 측 비밀번호 요청 장부나 새 인증 체계를 추가하지 않았다. 서버의 기존 비밀번호 확인·세션 거래와 새 로그인 절차를 유지한다.

## 적용 조건·한계

고객 PR25 위의 별도 초안이다. 실제 서버 결합 검증은 서버 PR24 `b31f863f66a4bd998fcbc596b1245cce92aac59e`를 포함한 작업본을 기준으로 한다. 서버 파일·운영 기능·업무 규칙은 이 PR에서 바꾸지 않는다.

고객 순서: #5 → #9 → #10 → #12 → #14 → #15 → #16 → #17 → #18 → #19 → #20 → #21 → #25 → 이 PR.
서버 순서: #5 → #6 → #11 → #13 → #22 → #23 → #24.
부모를 main에 반영한 뒤 후속 PR을 main으로 재지정하고 코드·시험·CI의 양쪽 변경을 보존한다. Claude가 비공개 통합 시험·제한 적용·실기기 확인·병합·배포를 맡는다.

실제 비밀번호·운영 계정·Firestore·비공개 전체 게이트·모바일 실기기·배포 캐시 전환은 시험하지 않았다. 입력 보존은 같은 페이지가 살아 있는 동안이다. 화면을 떠나거나 새로고침할 때 비밀번호와 작성 내용을 별도 저장하거나 다른 계정으로 넘기지 않는다.

응답 유실 때문에 새 열쇠 자체를 받지 못했다면 클라이언트가 그 열쇠를 만들어 복원할 수는 없다. 로그인으로 변경 결과를 확인해야 한다. 모든 진행 중 계정 작업의 즉시 철회나 서버 비밀번호 요청의 멱등성을 보증하는 변경은 아니다.

## 게시 보류 — 별도 로그인 저장 충돌 재현

실제 앱 두 탭 반복에서 59/60, 잠금·저장소 추적에서 99/100이었다. 실패 기록은 첫 탭 잠금 해제 후 두 번째 탭이 잠금을 받았어도 이전 localStorage 값을 읽고 두 번째 교체에 성공하는 순서를 보여 준다. 앱 없는 직접 저장소 반복 200회는 모두 통과했으므로 그 좁은 결과로 실제 앱 실패를 배제하지 않는다.

비밀번호 보존 수정은 별도 작업본에 유지한다. 로그인 소유권 비교·교체를 트랜잭션 저장소 기준으로 보완한 뒤 합쳐 다시 검증하고 게시한다. 기존 token-store.js는 이번 비밀번호 구현에서 바꾸지 않았다. 관련 선행 PR들도 운영 반영을 완료한 상태가 아니다.

표준 근거: [WHATWG Web Storage](https://html.spec.whatwg.org/dev/webstorage.html)는 다중 프로세스의 에이전트 사이 localStorage 상호작용에 잠금 보장을 가정하지 않도록 설명한다. 이번 실행 기록에서 확인한 직렬 잠금 이후의 오래된 읽기는 그 문서만으로 추정한 것이 아니라 별도 브라우저 재현이다.
