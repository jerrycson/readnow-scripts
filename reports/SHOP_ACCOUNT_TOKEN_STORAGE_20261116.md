# 우리숍 로그인 정보 저장 실패와 기기 복구 — 2026-11-16

## 재현과 수정 범위

기준은 PR #17의 c95ecc7d3b27d28ad265fbd677a560b76867a64d다. 합성 자료·실제 Edge에서 bq-tok 쓰기 거절 뒤 로그인 열쇠는 없는데 회원 정보가 로그인한 상태로 캐시되는 문제와, 삭제 거절 뒤에도 로그아웃했다고 표시하는 문제를 재현했다. 원본 0/2, 수정 뒤 2/2다. 실제 운영에서 발생했다고 단정하지 않는다.

shop/token-store.js가 로그인 열쇠의 읽기·쓰기·삭제를 담당한다. 같은 출처의 Web Locks 안에서 예상한 이전 열쇠와 현재 값을 대조하고, 저장 뒤 다시 읽어 결과를 확인한다. 잠금 도구·저장소 접근·소유권 확인이 실패하면 무잠금 쓰기로 우회하지 않는다. 앞선 쓰기는 끝나고 확인 읽기만 실패했을 때는 같은 결과를 재확인하며 쓰기를 반복하지 않는다. 서로 다른 탭이 같은 이전 열쇠를 바꾸려 하면 먼저 저장한 한 쪽만 성공한다.

로그인·가입·시험 로그인·비밀번호 변경·로그아웃·탈퇴는 요청 전 저장 도구와 현재 소유자를 확인한다. 같은 탭에서 해당 처리가 진행 중이면 겹쳐 시작하지 않는다. 서버 처리를 마친 뒤 기기 저장만 실패하면 회원 캐시를 비우고 지속되는 안내와 ‘기기 저장만 다시/기기 정리만 다시’를 보여 준다. 이 버튼은 서버 요청을 반복하지 않는다. 비밀번호 변경·가입·탈퇴가 서버에서 끝났다는 사실과 기기 처리가 아직 남았다는 사실을 따로 알린다. 서버 로그아웃 응답을 확인하지 못한 경우에는 기기 정리와 서버 결과를 구분한다.

저장 대기 중에는 실패를 빈 로그인으로 숨겨 계정 요청을 보내지 않는다. shop.js의 인증 요청, shop-track.js의 문의·이용 기록도 엄격한 로그인 읽기를 사용한다. 상품 읽기는 유지한다. 다른 탭의 새로운 열쇠가 생겼으면 늦은 저장·삭제와 재시도를 폐기하고 새 로그인을 보존한다. 401 시험 계정 정리는 열쇠 삭제가 확인된 뒤에만 기존 장바구니 소유권 검사로 이어지며, 삭제 실패 때 시험 기록을 먼저 지우지 않는다.

## 적용과 한계

고객 가지 #5→#9→#10→#12→#14→#15→#16→#17 뒤 최신 main에 순서대로 통합한다. 부모 작업 가지에 병합하지 않는다. 서버 #5→#6→#11→#13, 공개 시험·CI·게이트의 합집합과 #13 주문 목록 함수를 보존한다. 새 token-store.js는 shop-acct.js 앞에 실어야 하며 shop.js·shop-acct.js·shop-track.js·index.html을 함께 반영한다. 판 번호·캐시 갱신은 Claude의 기존 배포 절차에서 처리한다.

Web Locks는 새 작성 경로 사이의 기기 저장을 조정한다. 이미 캐시된 옛 작성자, 서버의 세션 변경, 서로 다른 기기를 하나의 거래로 만드는 변경이 아니다. 서버 응답이 유실된 계정 작업의 결과를 확정하거나 이미 전송한 작업을 취소하지 않는다. 서버가 완료를 알렸지만 기기 저장만 실패한 경우에 한정해 로컬 재시도를 제공한다. 복구 대기 내용은 열린 탭의 메모리에만 두며 새 열쇠를 URL·추가 저장소·로그에 남기지 않는다. 창을 닫거나 새로 고친 뒤에도 이 복구가 유지된다고 보장하지 않는다.

모든 시험은 합성 자료이며 운영 연결을 차단했다. 운영 계정·주문·재고·문서·수집기 머리·판 번호·배포는 변경하지 않았고 수량 예약은 OFF다. 실제 Firestore·인증·실기기·옛 캐시 혼재·제한 적용은 Claude 재개 후 확인한다. 쪽지 병합, Claude 흡수, 운영 반영은 별개로 기록한다.
