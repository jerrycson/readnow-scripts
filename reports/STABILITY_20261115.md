# 출고 실행 안전성 보완

기준: a85ee6b2c715c2b562dfc2547c8da437ee91d245. 운영 데이터·배포 판 번호·수집기 헤더·HSIG 변경 없음. 이 문서는 코드 검토와 격리 시험 결과이며 운영 검증 완료 표시가 아니다.

## 변경 계약

- 실행 도구 또는 실행 기록 권한이 없으면 외부 변경을 보내지 않는다. 읽기 경로는 유지한다.
- 같은 출고 요청의 재시도는 operationId를 재사용한다. 실행 기록은 요청 해시와 시도 번호를 보관하며, 새 시도를 이전 결과가 덮지 못한다.
- 전송 뒤 예외·HTTP 오류·완료 기록 실패는 결과 불명으로 남긴다. 명시적 거절/전송 전 실패와 구분한다. 목록에 아직 남았다는 사실만으로 재전송 가능하다고 판정하지 않는다.
- 원스톱 담당권은 증가하는 epoch로 검사한다. 맥박·단계 기록·송장 생성·재개·원격 도우미 작업 생성에서 소유권을 검사한다.
- ALPS 전송 전 inFlight를 기록한다. 응답이 사라지면 다시 보내지 않으며, 도우미가 돌려주는 같은 operationId만 결과 확인의 근거로 쓴다. 이전 도우미 버전에서는 확인 대기가 유지될 수 있으므로 웹앱과 도우미의 배포 순서를 함께 검토한다.
- 송장은 발송 요청에서 사라졌다는 사실만으로 완료로 보지 않는다. 같은 송장번호를 직접 확인하며, 응답 불명 뒤 CSV 인코딩 변경 재전송·한 건씩 재입력을 보류한다. 실행 시도 표를 전송 전에 주문 항목에 보관한다.
- 보류는 실행 ID와 주문 ID를 연결한다. 상자 수, 파일 이름 또는 식별자가 없는 옛 기록만으로 주문을 보류로 분류하지 않는다.

## 검증

- 독립 안전성 시험 29건: 동시 실행·트랜잭션 재호출·권한 오류·도구 누락·결과 저장 실패·담당권 상실·ALPS 응답 유실·보류 식별을 가짜 데이터로 검증.
- 기존 tSHIPPC 29개 판정, tSENDPREP1115 7개 판정 통과. 실제 PC 연결 없이 기존 시험을 격리 실행.
- 변경 JavaScript와 웹앱의 인라인 스크립트 7개 구문 검사 통과.
- 비공개 브라우저 통합 시험 tSHIPMIX0/tSHIPHOLD1114 및 운영 실기기 시험은 Claude가 수행해야 한다. tSHIPHOLD1114의 도우미 fixture에는 새 식별 계약을 반영했고 기존 판정은 유지했다.
- `node src/tools/bench-shipping.cjs`는 같은 입력·결과로 31회 중앙값/P95를 비교한다. 준비 실행 조건을 맞춘 재현 스크립트에서 5천 주문의 보류 계산 중앙값 11.9→3.9ms, P95 14.2→6.2ms. 초기 탐색 측정(98.0→3.7ms)은 실행 환경의 준비 상태 차이가 있어 성과 기준으로 사용하지 않는다. 실제 화면의 로딩·메모리·Firestore 읽기량 성과로 해석하지 않는다.

## 적용과 복구

1. Claude가 최신 main과 다시 비교하고 비공개 통합 시험·배포 게이트를 실행한다. 이전 판의 진행 중/결과 불명 실행을 먼저 대조한다. 기존 작업의 번호를 바꾸거나 이전 판과 새 판을 동시에 새 업무의 작성자로 두지 않는다. 새 최초 요청은 두 PC와 자동/수동 경로가 같은 번호를 쓰고, 부분 취소 뒤 재결정은 남은 품목의 해시로 구분한다.
2. 도우미 operationId 응답을 먼저 확인하고 웹앱·수집기·클라우드의 같은 코드 판을 제한 적용한다.
3. MJ-MAIN·일반 사무실 PC·LOGGER에서 역할과 실행 기록을 관찰한다. 운영 쓰기·인쇄를 비교 시험으로 중복 실행하지 않는다.
4. 오류 시 새 작업을 보류한다. inFlight/unknown/exec_log를 삭제하거나 성공으로 강제 변경해 재시도하지 않는다. 외부 처리 결과를 확인하고 기록을 보존한다.

## 후속 순서

수량별 예약과 시험 게이트 → 운영 재고 기준 확인 후 제한 활성화 → 홈·출고·상품 목록·우리숍·연구의 같은 기기/데이터 성능 측정 → 측정된 구독·타이머·계산 병목부터 분리. 화면 전체 성능 검증과 노트·작업판 동시 편집 보존 시험은 아직 완료되지 않았다.
