# 정범 노트 자료 보존 검토 — 2026-11-16

## 문제와 고침

기존 `set` 요청으로 일부 칸만 보내면 생략한 본문이 사라질 수 있었다. 같은 메모를 두 기기에서 편집해도 마지막 요청이 먼저 저장된 글을 덮었다. 화면은 저장 전에 입력을 비웠고, 실패 시 되돌림 안내만 남겼다.

- `cloud/notes-guard.js`에 공용 저장 계약을 분리했다. 기존 문서의 생략한 칸과 최초 생성 시각을 보존한다.
- `body`, `text`, `draft`를 바꿀 때 편집을 시작하며 읽은 값을 `base`로 전달한다. Firestore 트랜잭션 안에서 현재 값과 비교하며 충돌 시 묶음 전체를 쓰지 않는다. 같은 값의 재전송은 허용한다. 상태·즐겨찾기 등 다른 칸의 부분 수정은 본문을 지우지 않는다.
- 웹앱과 MCP/암호문 입력이 같은 계약을 사용한다. 웹앱·아티팩트용 공용 코어에는 같은 보호 코드를 포함하고, 세 사본이 일치하는 시험을 둔다.
- 저장 확인 응답의 건수와 실패 목록을 검사한다. 작성한 내용은 전송 전에 기기에 임시 보존하고, 결과 불명·충돌·거절이면 ‘미저장 글’에서 확인한다. 재시도에는 원래 편집 기준을 유지한다. 저장 공간이 막히면 메모리 사본과 복사 안내를 남긴다.
- 웹앱 복구 사본은 로그인 사용자별 localStorage 키를 사용한다. 별도 키를 제공하지 않는 아티팩트는 해당 탭의 sessionStorage를 사용한다. 기기의 저장소를 지우면 사본도 없어지므로 서버 백업을 대체하지 않는다.
- 자동 초안 저장은 전송 순서를 지킨다. 다른 기기의 수정은 자동으로 합치지 않는다. 보내기 완료 기록은 그동안 들어온 새 초안을 비우지 않는다.
- 닫힌 화면의 입력 처리기·구독·타이머를 정리한다. 같은 DOM에 다시 열었을 때 옛 화면이 오래된 편집 기준으로 쓰는 경로를 브라우저 시험에서 재현하고 제거했다.
- 노트 경로를 필수 시험 정책에 연결하고, 시험용 복사본에도 공용 코어를 포함했다.

## 적용 전 Claude가 확인할 것

1. PR #5가 main에 반영된 다음 이 PR의 base를 main으로 바꾼다. 이 PR을 #5 가지로 병합하지 않는다. 수량 예약 PR #6의 활성화와 독립된 변경이다.
2. 비공개 아티팩트 저장 어댑터가 `ops[].base`를 보존하고 실제 서버의 `{n, bad}` 응답을 반환하도록 맞춘다. 새 공용 코어를 넣고 `RN_JBNOTE` 회귀 시험을 실행한다. 응답을 버리는 옛 어댑터는 새 코어에서 저장 확인 실패로 보인다.
3. 클라우드·웹앱·아티팩트 적용을 조율하고, 기존에 열린 옛 웹앱 탭을 새 판으로 갱신한다. 옛 탭의 직접 Firestore 쓰기는 새 서버 모듈만으로 막히지 않는다. 실제 Firestore 권한과 트랜잭션 한도, 오프라인 복구도 통합 시험한다.
4. 기존 작업판의 본문 저장 코드는 이 공개 저장소에 없다. 공개 `/board-in`은 숫자·표시를 전달하는 거울 경로다. 작업판 본문과 책방 친구 새 공간의 동시 편집 보존은 각각의 실제 구현에서 별도로 확인한다.
5. 아직 제출하지 않은 새 메모 입력칸·문장 선택 버블 전체를 영구 보관하는 기능까지 검증한 것은 아니다. 이번 복구 사본은 저장을 시도한 내용과 자동 저장 대상 초안을 다룬다.

배포·판 번호 변경·운영 자료 쓰기는 하지 않았다. 테스트 통과를 전체 운영 검증 완료로 간주하지 않는다.

## 설계 근거

Firestore의 트랜잭션은 읽은 문서가 바뀌면 콜백을 다시 실행하며, 성공한 트랜잭션의 쓰기는 함께 적용된다. 이에 따라 모든 읽기를 먼저 하고, 화면 상태 변경은 트랜잭션 콜백 밖에서 처리했다. 오프라인에서는 실패할 수 있어 별도의 미저장 사본을 남긴다. [Firebase 공식 문서](https://firebase.google.com/docs/firestore/manage-data/transactions)
