# 서가 화면 전환 경합과 반복 측정 — 2026-11-16

## 문제와 수정

서가 파일을 받는 동안 찜 화면으로 나갔다가 서가로 돌아오면, 이전 요청과 새 요청이 모두 현재 경로를 서가로 판단했다. 두 화면을 만들고 마지막 화면의 정리 함수만 보관해 이전 화면의 이벤트 듣개가 남았다. 늦은 파일 실패도 현재 다른 화면에 오류를 그릴 수 있었다.

shop/shop.js의 화면 요청 번호를 이동·새 요청마다 올리고, 파일과 설정 수신 후의 성공·실패·재시도 콜백에서 최신 번호를 확인한다. 서가 모듈·디자인·기억한 정렬·장바구니·주문 규칙·자료 캐시·판 번호는 바꾸지 않았다.

- 화면 이탈 후 이벤트 듣개는 두 크기 모두 수정 전 114, 수정 후 47. DOM 노드는 PC 3,728 → 443, 휴대폰 3,729 → 453. 숫자는 이 격리 조건의 CDP 측정값이며 운영 사이트 전체 수치가 아니다.

## 일반 전환 속도 측정

PC와 휴대폰 크기 각각 16회 서가↔찜 전환 중 첫 준비 1회를 제외한 15회씩, 3차례 측정했다. 같은 컴퓨터·자료·DPR 1·외부 글꼴/사진 없음. 아래는 각 회차의 중앙값 / P95(ms)이며, 전체 사용자 LCP·INP나 실제 휴대폰 성능이 아니다.

| 조건 | 1회 | 2회 | 3회 |
|---|---:|---:|---:|
| 수정 전 PC | 84.3 / 333.2 | 71.1 / 319.0 | 75.3 / 330.7 |
| 수정 전 휴대폰 크기 | 66.2 / 247.6 | 65.3 / 242.6 | 68.3 / 242.3 |
| 수정 후 PC | 85.8 / 313.8 | 68.5 / 327.3 | 90.9 / 318.2 |
| 수정 후 휴대폰 크기 | 67.5 / 238.8 | 65.0 / 237.9 | 67.1 / 238.1 |

일반 전환 시간은 회차별 변동이 겹치므로 속도 향상을 주장하지 않는다. PC 중앙값이 높게 나온 회차도 있어 실제 배포 후보에서 같은 조건 재측정이 필요하다. 반영 근거는 빠른 화면 전환에서 재현된 중복 생성·잔류 듣개 제거다. 정상 전환에서는 양쪽 모두 16개 생성·16개 정리, 이탈 후 듣개 47개, DOM PC 444·휴대폰 454개로 같았다. 목록 읽기 요청도 두 화면 크기를 합해 /shop/shelf 2회로 같았다.
