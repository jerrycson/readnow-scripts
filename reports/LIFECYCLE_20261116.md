# 화면과 조회가 끝난 뒤 남는 실행 정리

기준: 출고 안전성 PR #5의 f11a47bc101a134e1badb808e5a9b0fddf0f5ddb. 기능의 입력·결과·권한·업무 단계는 유지한다. 운영 자료와 배포는 변경하지 않았다.

## 재현과 수정

| 경로 | 재현한 문제 | 바꾼 종료 처리 |
|---|---|---|
| 매입 화면 도서 조회 `purRemote` | 읽기 오류로 사용자에게 끝났다고 반환한 뒤에도 60초 타이머가 남아 대기 작업을 취소할 수 있음 | 성공·읽기 오류·구독 시작 실패·시간 초과가 모두 같은 종료 함수를 사용. 타이머·구독 해제는 한 번만 수행 |
| 사진 읽기 진행 표시 `kmsProgDraw` | 화면을 닫은 뒤 작업이 끝나면 DOM 검사에서 먼저 반환해 1초 타이머가 계속 남음 | 화면 유무에 앞서 끝난 작업의 타이머 정리 |
| 출고 가벼운 모드 | 전체 자료 받기를 시작한 뒤에도 1초마다 전환 조건 검사 | 기존 출고 화면·뒤로 가기 조건 유지. 전환 후 감시 종료, 중복 등록도 방지 |

조회가 실제로 60초를 넘긴 경우에는 기존대로 queued 작업만 취소한다. 이미 실행 중인 작업은 취소하지 않는다. 읽기 오류 자체를 성공으로 바꾸지 않는다. 도서 조회가 끝나는 순서가 바뀌어도 뒤늦은 응답이 정리를 반복하지 않는다.

가짜 시계에서 각 종료 뒤 남는 타이머가 1개에서 0개로 줄어드는 것을 확인했다. Firestore SDK 내부의 구독 수나 실제 서버 읽기 비용을 측정한 수치는 아니다. 즉시 응답·구독 시작 예외 시험은 어댑터 경계의 방어 검증이며 실제 Firestore가 동기로 응답한다는 주장이 아니다.

## 검증과 한계

- 새 공개 시험 `tLIFECYCLE`: 12/12 통과. 성공·오류·시간 초과·늦은 응답, 화면 이탈, 뒤로 가기, 중복 감시를 포함.
- 기존 독립 검증 49/49 통과. 구문 검사와 출고 안전성 시험 포함.
- `src/app.html` 변경 시 필수 시험에 연결하고 GitHub CI에도 실행을 추가.
- 실제 인증된 운영 화면, 기기별 장시간 메모리, Firestore 읽기 수, 비공개 매입 화면 시험(tpf2)은 Claude 통합 확인이 남음.

## 측정에 따라 보류한 후보

통합 장부 ledBuild와 mcPlan을 가짜 상품 1천/5천/2만 건으로 31회씩 측정했다. 반복 배열 생성과 판매처 이름 찾기를 줄인 후보는 2만 건 중앙값 53.75→51.03ms, P95 65.86→65.72ms였고 1천 건 중앙값은 2.53→2.69ms로 악화했다. 오차를 넘는 일관된 개선을 확인하지 못해 해당 계산 변경은 이 PR에 넣지 않았다. 이 측정은 순수 계산이며 화면 전체 속도를 뜻하지 않는다.
