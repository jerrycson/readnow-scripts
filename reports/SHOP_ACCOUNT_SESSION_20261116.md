# 우리숍 계정 전환과 늦은 화면 응답 보호 — 2026-11-16

## 재현한 문제

기준은 PR #16의 8d84250639e880872a820acc744d42acd23b4e82다. 합성 자료로 실제 Edge를 열어 다음 네 검사가 실패하는 것을 확인했다: 내 정보의 늦은 인증 실패가 이동한 찜 화면을 덮는 PC·휴대폰 두 경로, 이전 로그인에서 예약한 찜 저장이 새 로그인 Authorization으로 전송되는 경로, 공개 북리스트의 늦은 실패가 현재 화면을 덮는 경로. 운영에서 발생했다고 단정하지 않는다.

## 요청·화면·계정 상태의 경계

인증 요청은 시작 시점의 로그인 열쇠를 ownerToken으로 고정한다. 서버 선택을 기다린 뒤 실제 전송하기 직전에 현재 로그인과 대조하며, 바뀌었으면 전송하지 않는다. 계정 창구 A는 응답 뒤에도 같은 소유자를 확인한다. 계정 저장 기능 지원 표시가 없는 옛 요청 도구로 우회하지 않는다.

찜 3초·최근 본 책 10초 예약은 예약 당시 계정에 묶는다. 로그인 전환 뒤 예약이 실행돼도 새 계정으로 보내지 않는다. 같은 계정에서는 기존처럼 마지막 목록을 모아 저장한다. 회원 정보·리뷰·서재·알림의 작성 요청도 해당 화면에서 정한 소유자를 사용한다. 전환 뒤 남아 있는 회원 정보 폼을 제출하면 입력을 보존하고 현재 계정에서 다시 확인하도록 안내한다.

계정 정보 캐시와 알림 수는 로그인 소유자가 바뀌면 재사용하지 않는다. 같은 주소로 돌아와 새 조회를 시작한 뒤 옛 조회가 끝나도 최신 계정 정보를 덮지 않는다. 내 정보·로그인·공개 서재·북리스트는 공용 화면 세대를 확인해 떠난 화면의 성공·실패를 현재 화면에 붙이지 않는다.

늦은 로그인·시험 로그인·비밀번호 변경 응답이 새 로그인 열쇠를 덮지 않게 하고, 과거 로그아웃 완료가 새 열쇠를 지우지 않게 한다. 정상 비밀번호 변경 뒤에는 새 열쇠로 계정 화면을 다시 읽어 다음 저장을 계속 사용할 수 있다. #15의 시험 계정 401/장바구니 보호를 유지한다. 계정 주문 목록 함수는 이 PR에서 교체하지 않고 #13과 별도 통합한다.

이미 외부 서버에 보낸 작업의 실행을 취소하는 변경은 아니다. 예를 들어 전송한 비밀번호 변경은 서버에서 완료되어 다른 세션이 만료될 수 있다. 늦은 응답을 새 로그인 상태에 적용하지 않는 것과 서버 작업이 실행되지 않았다는 것은 구분한다. 실제 결과가 필요한 경우 현재 계정에서 다시 확인해야 한다.
