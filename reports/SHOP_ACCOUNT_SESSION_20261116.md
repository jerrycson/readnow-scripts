# 우리숍 로그인·일회용 시험 열쇠의 원자적 세션 갱신 — 2026-11-16

서버 PR #22의 a688efa3edf727327782356e27741e2f8228cc05를 기준으로 실제 회원 함수를 합성 저장소에서 실행했다. 두 서버가 같은 일회용 시험 열쇠로 동시에 들어가면 모두 성공했다. 이전 열쇠 요청이 새로 발급된 열쇠를 소비 처리했고, 늦은 로그아웃은 새 세션을 지우며 폐기된 세션을 다시 저장했다. 같은 세 재현은 원본 0/3 → 수정본 3/3이다. 운영 발생을 단정하지 않는다.

## 구현

일회용 열쇠 검증·소비와 세션 추가를 같은 Firestore 거래로 처리한다. 최신 문서에서 시험 표시와 시험 메일의 두 조건, 계정 상태, 열쇠 해시·만료를 다시 확인한다. 새 열쇠로 바뀌었거나 이미 소비된 열쇠면 쓰지 않는다. 커밋 뒤 응답이 유실되어도 같은 열쇠를 다시 소비해 추가 로그인 토큰을 발급하지 않는다.

일반 로그인은 비밀번호 확인 뒤 거래에서 최신 회원·메일 색인·확인한 비밀번호 해시를 대조한다. 그 사이 비밀번호·메일 연결·계정 상태가 바뀌면 발급을 보류한다. 최신 세션 배열에 새 기기를 추가하므로 동시 로그인이나 시험 진입이 서로의 토큰을 덮지 않는다. 비밀번호 계산은 거래 재실행마다 반복하지 않는다.

로그아웃은 거래에서 유효한 현재 요청 세션을 확인하고 그 세션만 제거한다. 비밀번호 변경도 최신 세션과 확인한 비밀번호 해시가 유효할 때 암호 해시와 새 세션 하나를 함께 저장한다. 거래 성공·실패·응답 불명 모두 해당 서버의 회원 캐시를 비운다. 일반 로그인 90일·5기기, 시험 열쇠 5분·1회와 설정된 로그인 시간, 비밀번호 규칙, 시험 계정 주문 금지는 유지한다.

Firestore 거래의 읽기-쓰기 순서와 재실행 계약을 따른다. [공식 거래 문서](https://firebase.google.com/docs/firestore/manage-data/transactions). 반환값은 최종 커밋한 거래 콜백에서 받고, 버려진 시도의 토큰·성공 판정·로그를 밖으로 보내지 않는다.

합성 거래 모델은 순차 확정·원자적 반영·읽기 후 쓰기·재실행을 검증한다. 실제 Firestore 잠금·보안 규칙·서비스 부하를 검증한 것은 아니다.
