# 손님 화면의 이전 응답 차단과 주문서 초안 보존 — 2026-11-16

## 문제와 보완

서가 PR #9(11b28582) 뒤 상품·목록·주문 관련 화면의 응답 순서를 검토했다. 실제 브라우저에서 지연 응답을 조절한 17개 사례 중 기존 소스는 12개 실패·5개 통과, 수정본은 17개 통과했다. 첫 11개 재현에서는 10개가 실패했고, 이후 정상 재시도·현재 합계·이전 합계·취소 후 이동 사례를 더했다.

- 이전 상품의 오류가 현재 작성 중인 주문서를 지움(PC 1280px·휴대폰 크기 390px).
- 같은 상품·홈으로 재진입하면 이전 응답이 최신 상품명/가격·목록을 덮음.
- 분류·요약 목록의 늦은 오류는 사라진 DOM을 고치다 오류가 나고, 주문 조회·장바구니·주문서·구매 안내의 늦은 응답은 현재 다른 화면을 덮음.
- 옛 주문서 합계 응답이 새 장바구니 값을 고치거나, 취소 완료 후 이전 주문 조회를 다시 그림.
- 기존 검색 목록의 상품 본문은 잡아 둔 DOM 연결 여부를 확인해 원래도 보호됨. 해당 동작을 회귀 시험에 유지했다. 분류 줄과 저장된 스크롤 복원에도 현재 요청 확인을 추가했다.

공통 pageScope()는 화면 요청 번호와 주소를 보관한다. 경로 전환과 새 비동기 화면 생성 때 번호를 바꾸고 성공·실패·재시도·합계 반영 전에 확인한다. 홈·분류·검색·요약 목록·상품·장바구니·주문서·주문 조회·구매 안내 9개 페이지에 적용했다. 이미 보낸 주문·취소 요청을 중단하거나 재전송하지 않는다. 취소 성공 안내는 유지하고 다른 화면으로 이동했다면 주문 조회만 다시 그리지 않는다.

주문서 초안은 입력 300ms 뒤 현재 문서에서 값을 다시 읽어 저장하므로 빠른 화면 이탈·즉시 재진입 시 이름과 받는 분이 사라지고, 빠른 주문 성공 뒤 삭제한 초안이 빈 값으로 다시 생겼다. PR 최초 머리 92154f0d에 추가한 6개 브라우저 사례 중 4개가 실패했다. 현재 주문서의 허용된 10개 입력 칸과 받는 분 동일 여부를 input/change 시점에 저장하고, 사라진 폼은 무시한다. 늦게 실행할 저장 타이머를 없앴다. sessionStorage와 기존 보관 범위를 유지하며 동의·쿠폰·숨김 칸은 저장하지 않는다. 저장 권한 오류 때 현재 입력과 주문 동작을 보존한다. 저장 실패 안내를 새로 추가하거나 다른 장치에 초안을 공유하지 않는다.

같은 주문서 안에서도 최초 합계 요청과 쿠폰 적용 요청이 겹칠 수 있다. a394725e에서 쿠폰 적용 뒤 1,800원으로 바뀐 합계를 늦은 최초 응답이 2,000원으로 되돌렸고, 최신 쿠폰 조회가 실패한 경우에도 옛 응답이 가격을 바꿨다(추가 2개 모두 실패). 합계 요청마다 번호를 늘려 현재 화면이면서 최신 요청인 결과만 가격·장바구니에 반영한다. 서버의 주문 합계 재검증과 기존 쿠폰 선택 규칙은 유지한다.

제출 응답 지연 재현에서는 ecea3afd의 세 사례가 모두 실패했다. 새로 담은 다른 상품과 새 초안을 이전 성공 응답이 지우고, 이동 뒤 거절 응답은 없는 오류 칸에 쓰려다 예외가 났다. 다음을 보완했다.

- 장바구니 줄에 이 기기 안에서만 쓰는 _entry를 붙인다. 주문에는 기존 상품 번호·수량만 보낸다. 접수한 줄과 수량만 순수 함수 cartAfterOrder로 정리하고, 추가 수량·삭제 후 다시 담은 줄·다른 상품은 남긴다. 남은 수량은 새 줄로 취급해 같은 결과를 다시 적용해도 재차 차감하지 않는다. 옛 탭처럼 줄 번호가 없는 값은 추측으로 제거하지 않는다.
- 초안 저장 차례와 저장 내용을 제출 때 기억한다. 이후 수정한 초안은 이전 주문 성공으로 지우지 않는다. 다른 화면으로 이동해도 성공 주문은 기존 내 주문 기록에 남기며, 해당 화면을 강제로 이전 주문 조회로 바꾸지 않는다. 새 주문서가 열려 있으면 입력은 두고 합계/품목만 새 장바구니에 맞춘다.
- 다른 화면으로 이동한 뒤의 거절·가격 재조회는 이전 폼을 고치지 않는다. 같은 탭에서 요청이 처리 중이면 반복 제출·주문서 재진입 후 제출도 보내지 않는다. 명시적 거절 뒤 기존 재제출은 유지한다.
- 계산 파일이 옛 캐시에 남아 cartAfterOrder가 없으면 주문 전 새로고침을 안내한다. 실제 캐시 교체·판 번호·배포 검사는 Claude가 맡는다.

## 적용 원칙과 근거

[React 공식 비동기 조회 예제](https://react.dev/reference/react/useEffect#fetching-data-with-effects)는 화면의 이전 요청을 무효화해 순서가 뒤바뀐 응답을 무시한다. 이 원칙을 현재 순수 JavaScript 화면의 증가하는 번호로 적용했으며 React나 새 화면 프레임워크를 도입하지 않았다. [Playwright 공식 CI 안내](https://playwright.dev/docs/ci-intro)의 브라우저 설치·자동 실행 절차를 참고해 공개 CI에도 실제 브라우저 검사를 추가했다. Playwright 1.62.1은 현재 로컬 도구 및 npm 게시 버전을 확인하고 고정했다.
