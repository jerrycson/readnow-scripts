# 손님 화면의 이전 응답 차단 — 2026-11-16

## 문제와 보완

서가 PR #9(11b28582) 뒤 상품·목록·주문 관련 화면의 응답 순서를 검토했다. 실제 브라우저에서 지연 응답을 조절한 17개 사례 중 기존 소스는 12개 실패·5개 통과, 수정본은 17개 통과했다. 첫 11개 재현에서는 10개가 실패했고, 이후 정상 재시도·현재 합계·이전 합계·취소 후 이동 사례를 더했다.

- 이전 상품의 오류가 현재 작성 중인 주문서를 지움(PC 1280px·휴대폰 크기 390px).
- 같은 상품·홈으로 재진입하면 이전 응답이 최신 상품명/가격·목록을 덮음.
- 분류·요약 목록의 늦은 오류는 사라진 DOM을 고치다 오류가 나고, 주문 조회·장바구니·주문서·구매 안내의 늦은 응답은 현재 다른 화면을 덮음.
- 옛 주문서 합계 응답이 새 장바구니 값을 고치거나, 취소 완료 후 이전 주문 조회를 다시 그림.
- 기존 검색 목록의 상품 본문은 잡아 둔 DOM 연결 여부를 확인해 원래도 보호됨. 해당 동작을 회귀 시험에 유지했다. 분류 줄과 저장된 스크롤 복원에도 현재 요청 확인을 추가했다.

공통 pageScope()는 화면 요청 번호와 주소를 보관한다. 경로 전환과 새 비동기 화면 생성 때 번호를 바꾸고 성공·실패·재시도·합계 반영 전에 확인한다. 홈·분류·검색·요약 목록·상품·장바구니·주문서·주문 조회·구매 안내 9개 페이지에 적용했다. 이미 보낸 주문·취소 요청을 중단하거나 재전송하지 않는다. 취소 성공 안내는 유지하고 다른 화면으로 이동했다면 주문 조회만 다시 그리지 않는다.

## 적용 원칙과 근거

[React 공식 비동기 조회 예제](https://react.dev/reference/react/useEffect#fetching-data-with-effects)는 화면의 이전 요청을 무효화해 순서가 뒤바뀐 응답을 무시한다. 이 원칙을 현재 순수 JavaScript 화면의 증가하는 번호로 적용했으며 React나 새 화면 프레임워크를 도입하지 않았다. [Playwright 공식 CI 안내](https://playwright.dev/docs/ci-intro)의 브라우저 설치·자동 실행 절차를 참고해 공개 CI에도 실제 브라우저 검사를 추가했다. Playwright 1.62.1은 현재 로컬 도구 및 npm 게시 버전을 확인하고 고정했다.
